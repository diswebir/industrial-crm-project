# فاز سوم — آزمون پذیرش نسخه ۲٫۰٫۰

این سند معیارهای پذیرش هر یک از ۹ تسک را به‌صورت قابل‌آزمون تعریف می‌کند. هر بند
شامل «کاربری که تست می‌کند»، «مرحله اجرا» و «نتیجه مورد انتظار» است.

## وضعیت ابزارهای تست در این محیط

- ✅ `tsc --noEmit` و `npm run build` فرانت‌اند بدون خطا اجرا شد.
- ✅ همه فایل‌های PHP بک‌اند با `php-parser` از نظر نحوی (Syntax) بررسی و تأیید شدند.
- ✅ صحت نحوی `deploy/cpanel/build.sh` با `bash -n` بررسی شد.
- ⚠️ در این محیط PHP runtime و دیتابیس MySQL در دسترس نیست؛ اجرای واقعی
  `php artisan migrate` و تست HTTP باید روی هاست یا محیط CI انجام شود
  (`deploy/cpanel/update.php` یا `php artisan migrate --force`).

## آزمون دود (Smoke) روی نسخه ارتقا‌یافته

1. همه کاربران قبلی می‌توانند با همان رمز وارد شوند.
2. فهرست مشتریان، پرونده مشتری، دستگاه‌های تخصیص‌یافته و سوابق سرویس بدون تغییر
   نمایش داده می‌شوند.
3. خروجی اکسل نسخه ۱ همچنان کار می‌کند (آدرس قبلی).
4. داشبورد، پیامک و تنظیمات بدون خطا باز می‌شوند.
5. تعداد مشتریان و دستگاه‌های تخصیص‌یافته قبل و بعد از ارتقا یکسان است:

```sql
SELECT COUNT(*) FROM customers;
SELECT COUNT(*) FROM customer_parts;
SELECT SUM(quantity) FROM customer_parts;
```

6. هیچ مایگریشن `Pending` یا خطای دیتابیس در `storage/logs/laravel.log` نیست.

## معیارهای عدم پذیرش (Fail)

- وجود هر گونه `قطعه` در UI یا API
- امکان دیدن/ویرایش مشتری خارج از دامنه دسترسی از طریق درخواست مستقیم
- منفی شدن موجودی انبار
- ثبت تخصیص بدون کسر موجودی یا ثبت لاگ
- پر شدن خودکار فرم ورود
- باز نشدن یا بریده شدن تقویم شمسی در مودال
- نبود اطلاعات دستگاه/فاکتور در خروجی اکسل
- خطای ۵۰۰ هنگام ثبت مشتری حقوقی بدون نام/موبایل
