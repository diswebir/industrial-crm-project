# راهنمای کامل ساخت بسته cPanel در ویندوز

این راهنما برای ساخت بسته **روی کامپیوتر خودتان** است. خروجی، دو فایل ZIP است که بعداً از طریق File Manager در cPanel آپلود می‌کنید. برای ساخت از WSL و Ubuntu استفاده می‌کنیم؛ نیازی به نصب Composer یا Node روی هاست نیست. اینترنت برای نصب پیش‌نیازها و دانلود وابستگی‌های پروژه لازم است.

> **وضعیت آزمون:** ساخت کامل با PHP و Composer و نصب نهایی روی cPanel در محیط فعلی آزمایش نشده است. پیش از استفاده عملیاتی، بسته را روی یک زیردامنه آزمایشی و دیتابیس خالی امتحان کنید.

## ۱. چیزهایی که لازم دارید

- ویندوز ۱۰ یا ۱۱ با قابلیت WSL 2 و دسترسی مدیر سیستم برای نصب اولیه.
- حداقل چند گیگابایت فضای خالی و اینترنت برای دریافت ابزارها و وابستگی‌ها.
- فایل‌های **نسخه فعلی پروژه با تغییرات نصب cPanel** روی کامپیوتر. دانلود نسخه قدیمی یا شاخه اصلی مخزن ممکن است این تغییرات را نداشته باشد. اگر کارتان در Arena ذخیره شده، ابتدا خروجی/نسخه همین تغییرات را دریافت کنید یا آنها را در مخزن خودتان منتشر و سپس دریافت کنید.
- هاست cPanel با Apache و `mod_rewrite`، PHP سازگار و MySQL. برای سادگی این راهنما PHP 8.4.1 یا بالاتر (نسخه 8.4) در رایانه و هاست پیشنهاد می‌شود. افزونه‌های موردنیاز هاست در راهنمای نصب ذکر شده‌اند. پیش از تهیه هاست نسخه و افزونه‌ها را با میزبان بررسی کنید.

این راهنما مخصوص نصب سایت در **ریشه یک دامنه یا زیردامنه** است، نه زیرپوشه‌ای مانند `example.com/crm`.

## ۲. نصب WSL و Ubuntu در ویندوز

PowerShell را با گزینه **Run as administrator** باز و اجرا کنید:

```powershell
wsl --install -d Ubuntu-24.04
```

اگر درخواست شد ویندوز را ری‌استارت کنید. سپس از منوی Start برنامه **Ubuntu 24.04 LTS** را باز کنید و نام کاربری و رمز لینوکس بسازید. هنگام تایپ رمز چیزی نمایش داده نمی‌شود؛ طبیعی است.

اگر WSL قبلاً نصب است، نام توزیع‌های قابل نصب را با `wsl --list --online` در PowerShell بررسی کنید. اگر `Ubuntu-24.04` در سیستم شما در دسترس نیست، طبق [راهنمای رسمی WSL](https://learn.microsoft.com/windows/wsl/install) آن را نصب کنید. دستورهای بعدی داخل پنجره **Ubuntu** هستند، نه PowerShell.

## ۳. نصب ابزارهای ساخت در Ubuntu

در ترمینال Ubuntu اجرا کنید. Ubuntu 24.04 به صورت پیش‌فرض PHP 8.3 دارد؛ برای PHP 8.4 در این راهنما از مخزن شخص ثالث Ondřej Surý استفاده می‌شود. نصب این مخزن نیازمند اعتماد شما به تأمین‌کننده آن است:

```bash
sudo apt update
sudo apt install -y software-properties-common
sudo add-apt-repository -y ppa:ondrej/php
sudo apt update
sudo apt install -y git curl unzip zip openssl composer php8.4-cli php8.4-mysql php8.4-mbstring php8.4-xml php8.4-curl php8.4-zip php8.4-gd php8.4-bcmath
sudo update-alternatives --set php /usr/bin/php8.4
```

برای نصب Node.js از nvm استفاده کنید. اگر هنگام مطالعه این راهنما نسخه جدیدتری از nvm منتشر شده، دستور رسمی را از [مستندات nvm](https://github.com/nvm-sh/nvm#installing-and-updating) بگیرید:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"
nvm install 22
nvm use 22
```

ابزارها را بررسی کنید:

```bash
php -v
composer --version
node -v
npm -v
zip -v | head -n 2
php -m
```

خروجی PHP باید 8.4.1 یا جدیدتر (ترجیحاً 8.4) و خروجی Node نسخه 22 باشد. اگر پس از باز کردن مجدد Ubuntu دستور `node` شناخته نشد، پنجره را مجدداً باز کنید یا دو خط `export NVM_DIR` و بارگذاری `nvm.sh` بالا را دوباره اجرا کنید. Node 22.12 یا جدیدتر برای Vite این پروژه لازم است.

## ۴. قرار دادن نسخه صحیح پروژه در Ubuntu

بهترین محل ساخت فایل‌های لینوکسی داخل پوشه خانگی Ubuntu است. فرض کنید پوشه پروژه با آخرین تغییرات را در ویندوز در مسیر زیر قرار داده‌اید:

```text
C:\Users\YOUR_WINDOWS_USER\Downloads\industrial-crm-project
```

در Ubuntu مسیر بالا را با نام کاربری واقعی ویندوز خود جایگزین و اجرا کنید:

```bash
mkdir -p ~/projects
cp -a "/mnt/c/Users/YOUR_WINDOWS_USER/Downloads/industrial-crm-project" ~/projects/industrial-crm-project
cd ~/projects/industrial-crm-project
```

اگر پوشه مقصد از قبل وجود دارد، پیش از کپی از آن پشتیبان بگیرید و مسیر مقصد جدید و خالی انتخاب کنید؛ در غیر این صورت ممکن است پوشه تو در تو ساخته شود یا نسخه‌های مختلف ترکیب شوند. نام مسیر بالا تنها مثال است. در این مرحله بررسی کنید واقعاً در ریشه پروژه هستید و تغییرات جدید را دارید:

```bash
pwd
ls deploy/cpanel/build.sh deploy/cpanel/paths.php backend/composer.lock frontend/package-lock.json
```

همه این فایل‌ها باید وجود داشته باشند. اگر پروژه را از Git دریافت می‌کنید، مطمئن شوید منبع شما شامل تغییرات این جلسه است؛ دریافت خودکار شاخه `main` لزوماً کافی نیست. پس از ساخت اولیه، برای دریافت تغییرات جدید باید فایل‌های اصلاح‌شده را دوباره به محل ساخت منتقل کنید.

## ۵. ساخت ZIPها

در ریشه پروژه در ترمینال Ubuntu:

```bash
bash deploy/cpanel/build.sh
```

اسکریپت وابستگی‌های PHP را با Composer نصب می‌کند، با `npm ci` فرانت‌اند را می‌سازد و دو بسته را در پوشه `cpanel-release` قرار می‌دهد. اولین اجرا ممکن است چند دقیقه طول بکشد. نباید هنگام اجرا سیستم خاموش یا اینترنت قطع شود. وجود پیام `Built` و بازگشت بدون خطا نشانه پایان اسکریپت است؛ با دستور زیر خروجی را ببینید:

```bash
ls -lh cpanel-release/cpanel-*.zip
unzip -t cpanel-release/cpanel-public.zip | tail -n 1
unzip -t cpanel-release/cpanel-private.zip | tail -n 1
```

خروجی‌ها:

- `cpanel-public.zip`: فایل‌های قابل دسترس از وب، شامل فرانت‌اند، `index.php`، فایل `.htaccess` و نصب‌کننده.
- `cpanel-private.zip`: کد Laravel، وابستگی‌های Composer و فایل‌های خصوصی.

**فقط** ZIP عمومی را در DocumentRoot سایت استخراج کنید. ZIP خصوصی را هرگز داخل DocumentRoot یا پوشه‌ای که از اینترنت قابل مشاهده است استخراج یا نگهداری نکنید. خروجی‌ها را به هاست مستقیم آپلود کنید؛ روی رایانه لازم نیست آنها را باز و دوباره ZIP کنید.

برای باز کردن پوشه خروجی در File Explorer ویندوز از داخل Ubuntu:

```bash
explorer.exe "$(wslpath -w "$(pwd)/cpanel-release")"
```

اگر این دستور کار نکرد، در نوار آدرس File Explorer مسیر `\\wsl.localhost\Ubuntu-24.04\home` را باز کنید و وارد پوشه کاربر لینوکس خود و سپس `projects/industrial-crm-project/cpanel-release` شوید. می‌توانید دو ZIP را از آنجا به Downloads ویندوز کپی کنید.

## ۶. آپلود و نصب در cPanel

1. در cPanel یک دیتابیس MySQL **خالی** و کاربر آن بسازید و دسترسی‌های کامل به همان دیتابیس بدهید.
2. DocumentRoot دامنه را مثلاً روی `/home/USER/xx.example.com` قرار دهید. ZIP عمومی را در همان مسیر آپلود و استخراج کنید.
3. ZIP خصوصی را در مسیری مانند `/home/USER/private_pro/project1/myc` آپلود و استخراج کنید. این مسیر باید خارج از **تمام** DocumentRootها باشد. `USER` و مسیرها را مطابق حساب خود جایگزین کنید؛ اینها صرفاً مثال‌اند.
4. در پوشه عمومی فایل `paths.php` را ویرایش کنید تا به مسیر مطلق واقعی خصوصی اشاره کند:

   ```php
   return '/home/USER/private_pro/project1/myc';
   ```

   مسیر خصوصی باید مستقیماً شامل `artisan`، `vendor`، `bootstrap` و `storage` باشد؛ یک پوشه اضافه ناشی از استخراج ZIP باعث خطا می‌شود.
5. فایل `.install-token` را در پوشه خصوصی ایجاد کنید. محتوای آن را یک رشته تصادفی و محرمانه هگزادسیمال حداقل ۳۲ نویسه بگذارید. برای تولید یک کد امن در Ubuntu رایانه‌تان:

   ```bash
   openssl rand -hex 32
   ```

   خروجی را در فایل خصوصی قرار دهید و محرمانه نگه دارید. این کد را در URL یا پوشه عمومی قرار ندهید.
6. SSL دامنه را فعال کنید؛ سپس `https://xx.example.com/install.php` را باز و کد نصب، آدرس سایت، اطلاعات دیتابیس و رمز قوی مدیر را وارد کنید. مدیر با `admin@crm.local` و همان رمز وارد می‌شود. نصب به صورت پیش‌فرض داده نمونه وارد نمی‌کند.
7. از حذف `install.php` در مسیر عمومی و `.install-token` در مسیر خصوصی پس از نصب مطمئن شوید؛ اگر باقی مانده‌اند دستی حذف کنید. همچنین ZIPهای آپلودشده را از هاست حذف کنید.
8. ورود، مسیر `/admin`، صفحه مستندات `/docs/api`، باز شدن مجدد صفحات داخلی و آپلود را روی هاست آزمایش کنید.

راهنمای دقیق‌تر تنظیمات، دسترسی‌ها، پیش‌نیازهای PHP و روش بازیابی/به‌روزرسانی: [`README.md`](README.md) در همین پوشه. برای مایگریشن به‌روزرسانی‌ها به Terminal/SSH یا کمک پشتیبانی هاست نیاز است.

## ۷. عیب‌یابی ساخت

- **`composer: command not found` یا `php: command not found`:** بسته‌های مرحله ۳ را داخل Ubuntu نصب کنید، نه فقط در ویندوز.
- **خطای `ext-... is missing`:** نام افزونه در خطای Composer را بخوانید، بسته مربوط به PHP 8.4 را نصب و با `php -m` بررسی کنید. افزونه‌ها باید روی هاست هم فعال باشند.
- **خطای ناسازگاری نسخه PHP:** `php -v` و `composer check-platform-reqs --no-dev` را داخل پوشه `backend` بررسی کنید. نسخه PHP و افزونه‌های هاست نیز باید با وابستگی‌های قفل‌شده سازگار باشند.
- **`node: command not found` یا نسخه قدیمی:** nvm را طبق مرحله ۳ بارگذاری کنید و `nvm use 22` بزنید.
- **خطای اتصال Composer یا npm:** اینترنت، DNS، پروکسی یا محدودیت دسترسی را بررسی و ساخت را مجدداً اجرا کنید. اگر نصب ناقص بود، خروجی آن را بدون اطلاعات محرمانه بررسی کنید.
- **`bash: ... No such file or directory`:** ابتدا با `cd ~/projects/industrial-crm-project` به ریشه درست بروید و وجود `deploy/cpanel/build.sh` را بررسی کنید.
- **خطای `$'\r': command not found`:** فایل اسکریپت با پایان خط ویندوزی ذخیره شده است. در Ubuntu `sed -i 's/\r$//' deploy/cpanel/build.sh` را اجرا و دوباره تلاش کنید.
- **خطای 500 یا نصب‌کننده در هاست:** مسیر واقعی `paths.php`، افزونه‌ها و دسترسی PHP به مسیرهای خصوصی و عمومی، از جمله محدودیت `open_basedir` را بررسی کنید. لاگ برنامه در `storage/logs/laravel.log` در مسیر خصوصی است. قبل از اشتراک‌گذاری لاگ، اطلاعات محرمانه را حذف کنید.

هر بار بعد از تغییر کد، دستور ساخت مرحله ۵ را مجدداً اجرا کنید و هر دو ZIP جدید را منتقل کنید. برای نصب موجود، ابتدا نسخه پشتیبان بگیرید و دستورالعمل به‌روزرسانی در راهنمای cPanel را رعایت کنید؛ فایل `.env`، `paths.php` و فایل‌های آپلودشده را بازنویسی نکنید.
