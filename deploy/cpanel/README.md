# نصب Industrial CRM روی cPanel با مسیرهای مجزای عمومی و خصوصی

این روش برای Apache با `mod_rewrite` و PHP 8.4.1 یا بالاتر است. برنامه React و Laravel روی یک دامنه و در ریشه آن نصب می‌شوند؛ نصب در زیرپوشه دامنه پشتیبانی نشده است. مسیر خصوصی باید خارج از **همه** DocumentRootهای قابل دسترسی از وب باشد، نه فقط خارج از مسیر این دامنه. `open_basedir` و دسترسی PHP نیز باید خواندن مسیر خصوصی را مجاز کنند.

## ساخت بسته

برای آموزش گام‌به‌گام ساخت روی ویندوز، [راهنمای ساخت بسته در ویندوز](راهنمای-ساخت-بسته-در-ویندوز.md) را ببینید.

روی یک رایانه یا محیط CI با PHP 8.4.1+، Composer، افزونه‌های PHP، Node.js 20.19+ یا 22.12+، npm، tar، zip و unzip:

```bash
bash deploy/cpanel/build.sh
```

دو فایل `cpanel-release/cpanel-private.zip` و `cpanel-release/cpanel-public.zip` ساخته می‌شود. برای ساخت آنها اینترنت لازم است؛ برای نصب بسته‌های آماده، Composer و Node روی هاست لازم نیستند. اسکریپت در پوشه موقت تمیز اجرا می‌شود و فایل‌های محلی `.env`، دیتابیس، فایل‌های آپلود و لاگ را در بسته قرار نمی‌دهد. در صورت خطا، پیام کامل را بررسی کنید؛ فایل‌های خروجی قدیمی تا مرحله انتشار حذف نمی‌شوند. از بسته‌های نسخه‌های قبلی استفاده نکنید. ساخت بسته در این مخزن خروجی آماده یا Release موجود را تضمین نمی‌کند.

## نصب

1. در cPanel یک پایگاه داده MySQL **خالی** و کاربر آن را بسازید و تمام دسترسی‌های لازم به همان پایگاه داده بدهید. نام و نام کاربر معمولاً پیشوند حساب cPanel دارند.
2. DocumentRoot دامنه را مثلاً `/home/USER/xx.example.com` تنظیم کنید. در File Manager فایل `cpanel-public.zip` را در آن مسیر و `cpanel-private.zip` را در `/home/USER/private_pro/project1/myc` استخراج کنید. مسیرهای فوق مثال‌اند؛ مسیر واقعی را از File Manager بگیرید. فایل‌های zip را پس از استخراج حذف کنید. هنگام استخراج نمایش فایل‌های مخفی را فعال کنید و از وجود `.htaccess` مطمئن شوید.
3. فایل عمومی `paths.php` را ویرایش کنید و مقدار return را به مسیر **مطلق واقعی** خصوصی تغییر دهید، مثلاً:
   ```php
   return '/home/USER/private_pro/project1/myc';
   ```
   این مسیر باید شامل `artisan`, `vendor`, `bootstrap` و `storage` باشد. پوشه خصوصی را هرگز داخل DocumentRoot قرار ندهید. مسیرهایی مثل `/private_pro/...` الزاماً همان `/home/USER/private_pro/...` نیستند.
4. برای فعال‌سازی نصب، با File Manager فایل `.install-token` را در پوشه **خصوصی** بسازید و یک رشته تصادفی محرمانه حداقل ۳۲ نویسه هگزادسیمال (فقط 0-9 و a-f) در آن قرار دهید. مثلاً با یک تولیدکننده امن تصادفی، یا `openssl rand -hex 32` در رایانه خود. این فایل را در مسیر عمومی نگذارید و کد را در اختیار دیگران قرار ندهید.
5. SSL را فعال کنید، سپس `https://xx.example.com/install.php` را باز کنید. کد نصب، اطلاعات دیتابیس، آدرس کامل سایت و رمز مدیر حداقل ۱۲ نویسه را وارد کنید. نصب‌کننده جدول‌ها را ایجاد می‌کند، نه داده‌های نمونه را. ورود مدیر با `admin@crm.local` یا `09120000000` و رمز انتخابی است.
6. اطمینان حاصل کنید که `install.php` و فایل خصوصی `.install-token` حذف شده‌اند؛ اگر باقی ماندند دستی حذفشان کنید. `APP_DEBUG` باید false بماند. از پایگاه داده، `.env` خصوصی، `storage` خصوصی و `storage` عمومی نسخه پشتیبان تهیه کنید. فایل‌های عمومی آپلودشده واقعاً عمومی هستند و برای محتوای محرمانه مناسب نیستند.

### پیش‌نیازها

PHP و افزونه‌های `pdo_mysql`, `mbstring`, `openssl`, `fileinfo`, `curl`, `tokenizer`, `xml`, `dom`, `xmlwriter`, `zip`, `gd`, `ctype`, `json` و `bcmath` را مطابق وابستگی‌های Composer روی هاست فعال کنید. دسترسی نوشتن PHP به `storage`, `bootstrap/cache`, پوشه خصوصی برای ایجاد `.env` و پوشه عمومی `storage` لازم است. از 755/775 متناسب با مالکیت استفاده کنید، نه 777. درخواست‌ها و `Authorization` باید توسط Apache به PHP برسند.

## بازیابی و به‌روزرسانی

پیش از به‌روزرسانی از دیتابیس و هر دو مسیر پشتیبان بگیرید. هرگز فایل `.env`، `paths.php` یا پوشه‌های `storage` را بازنویسی نکنید؛ فایل‌های نسخه جدید را با دقت جایگزین کنید. مایگریشن‌ها باید از طریق SSH/Terminal و در مسیر خصوصی با `php artisan migrate --force` اجرا شوند. اگر هاست امکان اجرای دستور ندارد از پشتیبانی هاست بخواهید این کار را انجام دهد. ابزار قدیمی `update.php` در بسته جدید قرار ندارد چون انتقال APP_KEY در URL امن نیست. بعد از ارتقا عملکرد ورود، `/api/v1/settings/company`، `/admin`، `/docs/api`، آدرس‌های داخلی React و آپلودها را بررسی کنید.

در صورت خطای نصب پس از ساخت `.env`، نصب مجدد خودکار مجاز نیست تا تنظیمات موجود بازنویسی نشوند. ابتدا لاگ خصوصی `storage/logs/laravel.log` را بررسی و بکاپ تهیه کنید؛ برای نصب مجدد روی دیتابیس خالی، `.env` و جدول‌های نصب ناقص را آگاهانه حذف کنید و توکن نصب را دوباره بسازید. تنظیمات یا اطلاعات دیتابیس و توکن را در اختیار عموم نگذارید.

> محدودیت: این راهنما وابسته به پیکربندی هاست واقعی است؛ در صورت محدودیت `open_basedir`، غیرفعال بودن rewrite یا عدم پشتیبانی PHP از افزونه‌ها باید با میزبان هماهنگ شود.

## آزمایش ساخت

`bash deploy/cpanel/tests/test-build.sh` بسته‌بندی و ساخت واقعی فرانت‌اند را بررسی می‌کند؛ PHP و Composer در این آزمون شبیه‌سازی شده‌اند. گردش کار `.github/workflows/cpanel-build.yml` علاوه بر آن، ساخت با PHP و Composer واقعی و نصب روی دیتابیس MySQL خالی را بررسی می‌کند. این آزمون جای بررسی نهایی روی هاست واقعی را نمی‌گیرد.
